# Устройство отключения сети

## Модель работы

Обычный запуск показывает меню. До выбора авто-режима проверки не выполняются. До срабатывания системная сеть не ограничивается этой программой. В авто-режиме первый полученный RU вызывает отключение без ожидания другого провайдера. Ошибка после подтверждённого начала мониторинга тоже вызывает отключение; при первом подключении действует ограниченный период ожидания доступности сети.

Монитор проверяет внешний адрес запросов к Cloudflare и IP.SB. Оба точных URL закреплены в коде. Проверки не дают знания о географии каждого пакета других приложений, маршрутов или одновременно IPv4/IPv6. Пакеты, отправленные до обнаружения, не отзываются.

## Порядок выключения

Сначала записывается журнал операции, затем ставится блокировка пакетов без исключений. После этого сохраняется состояние адаптеров, и они отключаются параллельно. Обнаружение повторяется, чтобы захватить адаптеры, появившиеся во время операции. В конце проверяется административное состояние найденных устройств. Успех подтверждается только при успешном системном фильтре, выключенных адаптерах и отсутствии ошибок команд.

Если операция не завершилась полностью, журнал сохраняется, а ошибки показываются отдельно. Отсутствие ответа одного адаптера не мешает попыткам отключить остальные. Второй процесс программы не допускается файловой блокировкой.

## macOS

PF включается через собственный enable reference. Текущий главный filter ruleset сохраняется через `pfctl -sr`. На время отключения главный filter ruleset заменяется единственным `block drop quick all` через `pfctl -R -f -`; NAT и конфигурация `/etc/pf.conf` не переписываются. Затем очищаются PF states, иначе существующие соединения обходили бы новые правила. Нормализационные scrub-строки в диагностическом выводе не считаются пользовательскими разрешениями.

Физические устройства определяются через `networksetup -listallhardwareports`: Wi-Fi, проводные, USB, Thunderbolt, bridge. Для каждого выполняются `ifconfig down`, выключение соответствующих сетевых служб, выключение Wi-Fi radio, затем повторный `ifconfig down`. Исходные enabled/up/radio состояния записываются для возврата.

При восстановлении главный filter ruleset возвращается из сохранённого снимка, освобождается только собственный PF token. Для снимка записывается идентификатор загрузки macOS: после перезагрузки ОС снимок и PF token предыдущей загрузки не применяются к новым правилам. Записанные состояния адаптеров сохраняются в постоянной папке и остаются доступны. Одновременные изменения PF другим администратором не объединяются автоматически: снимок отражает состояние до отключения. Не следует параллельно управлять главным PF ruleset другой программой.

## Linux

Отдельная nftables-таблица семейства inet содержит input/output/forward base chains с policy drop и без разрешающих правил. IPv4/IPv6 запрещаются одной транзакцией. Физические адаптеры выбираются по sysfs device, затем переводятся в down через iproute2. Если ими управлял NetworkManager, управление временно отключается через nmcli; при восстановлении возвращаются прежнее управление и UUID активного соединения.

При восстановлении удаляется только собственная таблица. nftables не фильтрует здесь все канальные протоколы: для отключения физического канала дополнительно выключается интерфейс. Неизвестный сетевой менеджер может пытаться поднять интерфейс; IP-фильтр остаётся дополнительной блокировкой.

## Windows

WFP получает отдельный sublayer. В одной транзакции добавляются безусловные BLOCK-фильтры для IPv4/IPv6: ALE connect/accept, transport, IP packet и forward. Условия-исключения отсутствуют. API используется через штатную fwpuclnt.dll, нужен 64-битный Python. Нет отключения Windows Defender Firewall или изменения его профилей.

Физические адаптеры перечисляются Get-NetAdapter -Physical -IncludeHidden и отключаются Disable-NetAdapter по точному InterfaceGuid. При восстановлении включаются только те, чей AdminStatus был Up. WFP-объекты удаляются по сохранённым GUID.

Фильтры WFP не dynamic и не persistent: они сохраняются при закрытии процесса, но не обещаются после перезапуска BFE/ОС. Состояние отключённых Windows-адаптеров может пережить перезагрузку. Программа не создаёт службы или задания автозапуска.

## Восстановление

В меню пользователь выбирает включение сети. Сначала откатывается сохранённый часовой пояс, затем возвращается состояние адаптеров, затем снимается пакетная блокировка. Если сохранён только часовой пояс без сетевого отключения, его откат выполняется отдельно. Повторный авто-запуск после отключения возвращает только сеть, сохраняя снимок приватности до явного полного отката. При ошибке восстановления фильтр и журнал сохраняются. Устройства, отключённые изначально, автоматически не включаются.

Повторный выбор авто-режима после отключения явно инициирует такое восстановление перед проверками. Между возвратом сети и получением безопасных ответов есть непроверенный интервал. Поэтому это детектор с аварийным отключением, а не непрерывный VPN kill switch без окна утечки.

## Хранение состояния

macOS: `/Library/Application Support/ALRU8 IP Monitor/state.json`. Linux: `/var/lib/alru8-ip-monitor/state.json`. Windows: `%ProgramFiles%\ALRU8 IP Monitor State\state.json`. Unix directory 0700, файл 0600; используются атомарная замена, fsync и блокировка второй копии. Файлы с символьными ссылками отвергаются. Журнал содержит настройки адаптеров и снимок правил, а не секреты VPN. Рядом хранится privacy.json (0600) с исходным часовым поясом, целевым поясом и стадией применения. Windows-снимок также хранит настройку DynamicDaylightTimeDisabled. Исходный снимок не перезаписывается при последующих сменах VPN-страны.

## Часовой пояс

GeoIP timezone читается только из утверждённого ответа IP.SB; имена зон фильтруются для безопасного вывода и сверяются со странами. Локальный справочник guard/data/timezones.json собран из системных zone.tab/zone1970.tab IANA TZDB, эти таблицы являются public domain. Совпадения одной страны недостаточно для угадывания региона: требуется конкретная зона ответа. Оба сервиса должны сообщить одну допустимую страну.

macOS использует systemsetup -gettimezone/-settimezone; Linux — timedatectl show/set-timezone. В Windows системная ICU переводит IANA в Windows ID, tzutil применяет его; исходная настройка DST читается через winreg и восстанавливается через tzutil. Часы UTC и NTP намеренно не перенастраиваются. Тесты подменяют все команды смены времени.

Перед изменением сохраняется исходное состояние. Проверка повторных раундов сверяет текущий системный пояс с последним применённым. Внешнее изменение, конфликт стран, отсутствие GeoIP timezone или ошибка применения вызывает аварийное отключение. Прерывание во время операции оставляет снимок для отката. При ошибке отката снимок сохраняется; установленный сетевой фильтр не снимается.

Глобальные службы автоматической геолокации, браузерные разрешения и WebRTC не изменяются. Даже согласованный GeoIP и timezone не доказывают отсутствия других идентифицирующих сигналов. Смена TZ действует после получения GeoIP и не отзывает уже раскрытую сайту информацию. Приложения могут кешировать пояс, а автоматические службы ОС могут менять его между проверками. Нативная смена и откат часовых поясов на целевых ОС в этой среде не выполнялись.

## Проверка и пределы

Тесты подменяют команды ОС. Они проверяют парсинг ответов и адаптеров, первый RU без ожидания медленного сервиса, порядок фильтра/отключения, сохранение исходных disabled-состояний, частичные ошибки и восстановление. Размеры WFP-структур проверяются отдельно. Нативные операции отключения в этой среде не выполнялись; подтверждение физического списка адаптеров macOS — только read-only проверка.

Для проверки на устройстве нужны: длинное IPv4/IPv6 соединение, ручное отключение из меню, контроль всех Wi-Fi/Ethernet/USB-путей, повторное включение, проверка ответов RU и захват физического трафика. Драйверы, служебные радиокадры, аппаратные offload, новые устройства после завершения, вмешательство администратора и сбой ОС не покрываются абсолютной гарантией «ни одного пакета».

Первичные описания команд: локальные `man pfctl`, `man ifconfig`, `networksetup -help`; [Microsoft Disable-NetAdapter](https://learn.microsoft.com/en-us/powershell/module/netadapter/disable-netadapter); [NetworkManager nmcli](https://networkmanager.pages.freedesktop.org/NetworkManager/NetworkManager/nmcli.html).
